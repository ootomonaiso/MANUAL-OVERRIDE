## 1. 監査目的

本監査では、次の2点を判定基準とした。

1. 変更された全ファイルが `docs/pixelart-rebuild` の要領書に沿って作成されているか。
2. 見た目以外の変更、特に当たり判定・物理・スコア・入力・スポーン・ジャンル遷移などのゲームプレイ機能への影響が発生していないか。

あわせて、先行調査 `docs/pixelart-rebuild/report.md` の調査内容と結論を独立に再検証した。

## 2. 総合判定

| 判定項目 | 結果 | 概要 |
|---|---|---|
| 要領書との整合 | **不合格** | 縦スクロール用スプライトの回転欠落、Survival描画の仕様不一致、承認仕様からの事後簡略化、未更新の実装記録などを確認 |
| ゲームプレイ非侵害 | **厳密には不合格** | 当たり判定等の直接変更はないが、描画側の `Math.random()` 削除により、後続のスポーン・アイテム抽選に使われるグローバル乱数列が変化する |

本変更を現状のまま「要領書適合・ゲームプレイ非侵害」として承認することは推奨しない。

## 4. 監査所見

### F-01: 縦スクロール時にプレイヤースプライトの向きが回転しない

**重要度: 高**  
**分類: 要領書不適合・表示不具合**

`src/game/sideScroller.ts:989` は縦スクロール時、プレイヤー描画コンテキストへ `-Math.PI / 2` の回転を適用する。

一方、`src/game/render/PixelCanvas.ts:382-388` の `sprite()` は次の順で描画する。

1. 現在の変換行列を用いて転送先の外接矩形を計算する。
2. `ctx.setTransform(1, 0, 0, 1, 0, 0)` で変換行列を解除する。
3. 算出した軸平行矩形へ、スプライト画像を回転させずに `drawImage()` する。

この処理では転送先の幅と高さは入れ替わるが、スプライト内部の画素方向は回転しない。

影響箇所には以下が含まれる。

- `src/genres/AerialStgPlugin.ts:227` — `player_aerial`
- `src/genres/AquaticPlugin.ts:134` — `player_diver`
- `src/genres/StgPlugin.ts:134` — `player_stg`

プリミティブで描かれた噴射炎などは座標変換によって回転するため、機体本体だけが右向きのまま、炎だけが縦向きになる可能性がある。特にAerialは、Q5で承認された「上向きに修正する」という目的を満たさない。

要領書 `00-rendering-system.md` のD2は、直角回転をデバイス空間スナップで解決済みとしている。しかし、矩形の外接範囲だけでなくスプライト画素の方向も維持する必要があり、現在の実装では解決されていない。

### F-02: 描画側の乱数削除がゲームプレイ用乱数列を変える

**重要度: 中**  
**分類: 間接的なゲームプレイ影響**

基準版では、以下の描画処理が毎フレーム `Math.random()` を消費していた。

- `StgPlugin.drawPlayer()` のエンジン炎: 1回
- `AerialStgPlugin.drawPlayer()` のエンジン炎: 1回
- `AerialStgPlugin._drawMissile()` のミサイル炎: 1回

現行実装では、これらが `runCycle` または `hazard.pulse` に基づく決定論的な2フレーム切替へ変更されている。

描画だけを見れば妥当な変更だが、本ゲームは描画とゲームプレイの双方で同じグローバル `Math.random()` を使用している。メインループは `src/game/sideScroller.ts:369-379` で更新後に描画し、後続フレームの `_spawnHazard()` は同ファイル `1188` 行以降で、障害物寸法、安全判定、アイテム出現・種類・位置などを `Math.random()` から決定する。

したがって、描画で消費される乱数の回数が変わると、以後のゲームプレイ抽選結果も変わる。

- 確率式や統計分布そのものは変更されていない。
- 当たり判定、スコア、入力、物理式を直接変更したものではない。
- ただし同じ乱数シードまたはモック列を与えても、基準版と同じ障害物・アイテム系列にはならない。

厳密な「ゲームプレイへの影響ゼロ」という判定には反する。

### F-03: Survivalの近接攻撃ハローが承認仕様と一致しない

**重要度: 中**  
**分類: 要領書不適合・演出変更**

`21-SurvivalFeature.md:69-79` は次を指定している。

- `SURVIVAL.meleeSwingShadowBlur` を `px.halo()` へ置換する際もJSON値を参照し続ける。
- `meleeActive / (meleeCooldown * meleeActiveRatio)` の減衰を `px.withAlpha()` で量子化する。
- 減衰式自体は変更しない。

現行の `src/game/systems/SurvivalFeature.ts:254-277` では、次の差異がある。

- `SURVIVAL.meleeSwingShadowBlur` を参照せず、ハロー段数に `PIXELART.haloSteps` を使用する。
- ハローは `withAlpha(fadeAlpha)` の外側で描画され、消滅直前まで等倍の明るさを維持する。
- フェードが適用されるのは攻撃弧の本体だけである。

個別要領書の実装記録にはこの差異が記載されているが、承認済み仕様の更新または追加承認を示すものではない。

### F-04: 仕様からの事後簡略化を「要領書どおり」と判定している

**重要度: 中**  
**分類: 手順・仕様適合性**

先行調査 `report.md:193-204` は、少なくとも次の簡略化を認識している。

1. `torch.json`、珊瑚・海藻・遺跡スプライトを作成せず、手続き描画へ変更
2. ステルス外套の楕円ディザを矩形ディザへ変更
3. Racingのホイール2フレームとヘッドライトハローを未実施
4. BulletRunnerの脚のネオンラインを省略
5. Puzzleのドロップシャドウを省略
6. sideScrollerのハザードHPバーを未変換

これらは個別要領書の「実際に行った作業内容」に理由付きで記録されているが、理由の事後記録は承認済み仕様との一致を意味しない。

`CLAUDE_OWNER.md:84-88` は、改善案や仕様変更についてユーザー確認を行い、承認されるまでは現行仕様のまま進めるよう求めている。RacingのQ6との対応を除き、上記簡略化について追加承認が得られた証跡は作業ツリー内で確認できなかった。

したがって、先行調査の「全26本が要領書に沿って完了」という判定は、厳密な監査基準では成立しない。

### F-06: PixelTextの転送位置がデバイス空間でスナップされない

**重要度: 低**  
**分類: 要領書不適合・表示リスク**

`00-rendering-system.md:129-166` は、`PixelCanvas` の出力を現在の変換行列でデバイス空間へ変換した後、グリッドへスナップするよう規定している。

しかし `src/game/render/PixelCanvas.ts:393-394` の `text()` は、座標変換やスナップを行わずに `PixelText.draw()` へ渡している。`src/game/render/PixelText.ts:133` も、算出した `dx` / `dy` をそのまま `ctx.drawImage()` に渡す。

`src/game/sideScroller.ts:774` の画面揺れは小数を含み得るため、その変換内で描かれるスコアポップアップなどが仮想ピクセルグリッドから外れる可能性がある。

### F-07: JSON検証が要領書で指定された網羅性を持たない

**重要度: 低**  
**分類: 検証不足**

`scripts/validate-json.mjs` には以下の不足がある。

- `SCHEMAS['pixelart.json']` の必須キーに `haloAlphaFalloff`、`ditherRatioSteps`、`spriteCacheMax`、`textCacheMax` が含まれない。
- `validatePixelart()` は欠落値を `continue` で読み飛ばすため、上記キーがなくても検証を通過する。
- コメントでは `schemas/sprite.schema.json` を単一の情報源として読むとしているが、実際にはスキーマファイルを読み込まず、検証条件を独自実装している。
- パレット色の正規表現 `#[0-9a-fA-F]{3,6}` は4桁・5桁のhexも許可する。要領書・JSON Schemaは3桁または6桁を想定している。
- `pixelart.json` は通常の設定検証と専用範囲検証の両方で成功件数に加算される。

また、`src/framework/ConfigValidator.ts:106` は `haloAlphaFalloff` の最小値を0としており、要領書の `0 < v <= 1` より緩い。

現在のデータ自体は有効であり直ちに実行時障害を起こすものではないが、「検証を要領書どおり実装済み」という評価はできない。

### F-08: 先行調査の変更ファイル一覧が全件を含まない

**重要度: 低**  
**分類: 監査範囲不足**

未追跡ファイル `.claude/launch.json` が追加されているが、PixelArt要領書にも先行調査の変更ファイル一覧にも記載されていない。

内容は開発サーバー起動設定であり、ゲームプレイへの影響は確認されない。しかしPixelArt実装に必要なファイルではなく、「変更された全ファイルが要領書に沿う」という監査基準には適合しない。

また、先行調査の「変更ファイル28件」は追跡済み差分の件数であり、未追跡62件を含めた作業ツリー全体の件数ではない。

## 5. ゲームプレイ非侵害の詳細判定

### 5.1 直接変更を確認しなかった領域

差分上、次のゲームプレイロジックに対する直接的な仕様変更は確認しなかった。

- プレイヤー・ハザードの当たり判定矩形
- 移動速度、重力、ジャンプ速度などの物理定数
- スコア加算式
- 入力キーと入力処理
- ジャンル選択・遷移条件
- スポーンテーブルの重みと確率式
- Survivalの空腹、近接攻撃判定、XP、アイテム取得処理

### 5.2 確認した間接影響

F-02のとおり、描画側で消費していたグローバル乱数が削除されたことで、後続のゲームプレイ抽選に使用される乱数位置が変化する。

この影響は、描画を行わない `reach-sim` や、確率分布だけを確認するテストでは検出できない。分布が同一でも、個々のプレイ結果や再現性は基準版から変わる。

よって本監査では、次のように区別して判定する。

- 直接的なゲームプレイロジック変更: **未検出**
- 実行結果へ波及する間接影響: **検出**
- 総合的な「影響なし」判定: **不可**

## 8. 修正優先順位

1. `PixelCanvas.sprite()` で回転・反転を含む現在の変換を正しく保持し、Aerial／Aquatic／STGを目視確認する。
2. 描画用乱数をゲームプレイ用乱数から分離するか、基準版と同じ乱数消費数を維持する方針を決定する。
3. SurvivalのハローへフェードとJSON設定を正しく反映する。
4. 仕様から簡略化した項目を、承認済み要領書へ戻すか、ユーザー承認を得て要領書を正式に更新する。
5. `00-rendering-system.md` と `17-RhythmPlugin.md` の実装記録を更新する。
6. PixelTextのデバイス空間スナップとJSON検証の不足を修正する。
7. `.claude/launch.json` を本ブランチへ含める必要性を判断し、不要なら変更対象から除外する。

## 9. 最終結論

先行調査は、テスト実行結果、既存unit失敗、直接的なゲームプレイ式の不変性については概ね正確だった。

一方で、スプライト転送時の回転喪失、描画乱数とゲームプレイ乱数の共有、承認仕様からの事後簡略化、検証コードの網羅性不足を見落としている。このため、先行調査の最終結論である「要領書に沿って完了」「ゲームプレイ機能への影響なし」は、独立監査の結果として支持できない。

**最終判定: 修正および再監査が必要。**

# 08. 戦闘画面 UI

対象範囲: 設計文書「戦闘画面のUI構成」

---

## 前提

**操作環境は PC のみを想定する。** タッチ環境への対応は考慮しない。
ただし**マウスオーバーだけで開閉する表示は置かない**（スキル枠へ手を伸ばす途中で一覧が勝手に伸び縮みし、
狙った枠が動いてしまうため）。開閉はクリックで行う。

---

## 画面配置

**手前側にプレイヤー、奥側に敵**を配置する。敵は `adjacent3` フォーカスが成立するよう、奥側で**左右方向に並べる**。

背景（`BattleBackdrop`）の上にキャラクターを重ね、左上に進行表示（`TurnBadge`）、
左上の下に常時表示のステータス・スキル一覧、右寄り・プレイヤー側の高さにコマンドを置く。
HP・予告は**キャラクターの身体には重ねず**、頭上（予告）と足元（HPプレート）の外側に置く。

```
┌──────────────────────────────────────────────┐
│[TURN M]                                       │
│[ステータス]     ── NEXT: 技名・被害の見込み ── │
│[スキル一覧]              [敵]   ← 床の際       │
│（常時表示）      ▬▬▬▬ 敵名  HP 12500/12500    │
│                                    ┌─────────┐│
│               ── スキル名の札 ──   │ COMMAND ││
│════════════════ 床の際 ═══════════│ BATTLE  ││
│                    [自キャラ]      │ INFO    ││
│特性・強化          ▬▬▬▬ あなた HP 15247/…  └─┘│
└──────────────────────────────────────────────┘
```

`BATTLE` を選ぶと COMMAND の位置に技の一覧が開く（CSS の入場アニメーションつき）。

```
                     ┌──────────────────────┐
                     │ ✦ クールダウン：-      │  ← 選択中の技の説明
                     │ 物理属性ダメージ:...   │
                     ├──────────────────────┤
                     │ ■ ファイアボール  Lv1 │
                     │ ■ 守る                │
                     │ ■ 避ける              │
                     │ ■ 何もしない          │
                     │   もどる              │
                     └──────────────────────┘
```

コンポーネント構成:

| コンポーネント | 役割 |
|---|---|
| `BattleScreen.vue` | 戦闘画面全体のレイアウト。以下を配置する |
| `BattleBackdrop.vue` | 背景（低解像度キャンバス + 手前の床。雲を `requestAnimationFrame` で流す） |
| `CharacterFrame.vue` | ドット絵 + 頭上の予告チップ + 足元のHPプレート + 被弾演出（自敵共通） |
| `PixelSprite.vue` | ドット絵1体分の描画（`src/data/sprites/*.json` を SVG 矩形へ展開） |
| `TurnBadge.vue` | 左上のターン数 |
| `CommandMenu.vue` | BATTLE / INFO の吹き出し |
| `SkillCommandPanel.vue` | 技の一覧と、選択中の技の説明 |
| `SkillCastBanner.vue` | 行動直前に出すスキル名の札 |
| `BuffStrip.vue` | 左下の「いま効いているもの」 |
| `StatusPanel.vue` | 左上・常時表示のステータス（要点だけの小さめ表示） |
| `SkillListPanel.vue` | 左上・常時表示のスキル一覧（同上） |
| `CharacterDetail.vue` | キャラクターをクリック、または COMMAND の INFO で開く大きく詳しい表示 |
| `SkillDraftPanel.vue` | 撃破後の3択 |
| `SkillText.vue` | 効果文の色分け |
| `HelpGuide.vue` | 右上のヘルプアイコン。直接押すと遊び方ガイド+用語集の全文、`GlossaryTerm` 経由だと押した用語の解説だけを帯で表示する |
| `GlossaryTerm.vue` | 「アクティブ」「STR」などの用語を押せるようにする薄いラッパー。定義は持たず `HelpGuide` の用語集を呼び出すだけ |

演出の振り分け（ポップアップ・フラッシュ・効果音・画面シェイク）は
コンポーネントではなく `composables/useBattlePresentation.ts` が担う（[09-effects.md](09-effects.md)）。

## ステータス表示パネル

画面左上（`TurnBadge` の下）に**常時表示**する。要点だけの小さめ表示にとどめ、
全ステータスの実効値/基礎値や所持スキルの説明文まで含む詳しい表示は
COMMAND の `INFO`（`CharacterDetail`）へ譲る。畳んだ状態でもいつでも開き直せる。

> **決定（改修時）**: 当初は COMMAND の `INFO` を押すたびにこのパネルを開閉する設計だったが、
> ステータスを見るためだけに毎回コマンドを1段掘り下げるのは手間が大きく、
> 戦況判断に使う情報を毎回隠すのも合わないため**常時表示に変更した**。
> `INFO` は「もっと詳しく見たい」ときのための大きな表示（`CharacterDetail`）を開く操作に変えている。

### 表示切替トグル（2軸・4パターン）

| 軸 | 選択肢 |
|---|---|
| 表示する値 | **基礎値** / **実効値** |
| バフ差分の表示 | **オン** / **オフ** |

表示例（基礎値 `10000`、実効値 `15000`）:

| 設定 | 表示 |
|---|---|
| 基礎値・バフオフ | `HP : 10000` |
| 実効値・バフオフ | `HP : 15000` |
| 基礎値・バフオン | `HP : 10000 +5000` |
| 実効値・バフオン | `HP : 15000 +5000`（`+5000` を**灰色**で目立たなく） |

**`+5000` は「実効値と基礎値の差」であり、実数バフの値ではない。** 実数バフと倍率バフの両方を適用した結果の差分を表示する。

```ts
const diff = computed(() => effective.value - base.value)
```

実効値表示時に差分を灰色にするのは、主たる情報が実効値そのもので差分は補足に過ぎないため。

### 差分の符号

差分が負（デバフ）の場合は `-3000` のように符号を付けて表示する。色は差分の正負で分ける（正=強調色、負=警告色、実効値表示時は両方とも灰色）。

> **決定（Q12）**: デバフが存在する以上、負の差分は起こりうるため **符号付きで表示し色で区別する**。

### トグルの永続化

トグルの選択状態は**戦闘をまたいで保持する**（ラン中は維持）。ラン終了でリセットする。

## スキル一覧パネル

ステータス表示パネルの下に**常時表示**する。**折りたたみ式**（既定は開いた状態）。

### 表示順

**上部（所持しているもの）**

1. セット中のアクティブスキル
2. パッシブスキル
3. 特性

**下部（未入手のもの）**

1. 未入手のアクティブスキル
2. 未入手のパッシブスキル
3. 未入手の特性

保管中（枠から外した）アクティブスキルは、**所持側の「セット中のアクティブスキル」の後**に、保管中と分かる形で表示する。

> **決定（Q13）**: 所持しているものである以上、未入手側ではなく **所持側** に置く。

### 未入手の開示段階

未入手のものは**スキル名のみ**を表示し、**アイコンは灰色**にする。効果の詳細は伏せる。

一度でも目にしたものは順次開示される（[06-draft.md](06-draft.md) の既見フラグ）。

| 状態 | 表示 |
|---|---|
| 未見 | 名前のみ・アイコン灰色・効果は伏せる |
| 既見（未入手） | 効果も表示・アイコン灰色 |
| 所持 | 効果も表示・アイコン通常色・レベルとスタックも表示 |

### 操作

- **クリック**: 詳細を開く／閉じる

同時に開くのは**1つのみ**。別の項目をクリックすると切り替わる。

> **決定（改修時）**: 当初はマウスオーバーでも開く設計だったが、カーソルが通過するだけで
> 一覧の高さが変わり、下にあるスキル枠が動いてしまうため**ホバーでの開閉は廃止した**。
> クリックでの開閉は変更していない。

## ドット絵として描く

`docs/pixelart-rebuild/00-rendering-system.md` の方針（座標と色をピクセルグリッドへ量子化する）を
戦闘画面にも適用する。canvas ゲーム側とは実装が別なので、DOM 側では次の2点で担保する。

| 対象 | 方法 |
|---|---|
| 背景 | 320×180 のキャンバスへ描き、`image-rendering: pixelated` で拡大する。空は段階的な帯、光源は四角い輪、地面は明暗のドットで表す（円弧・無段階グラデーションを使わない） |
| キャラクター | SVG の矩形として描き、表示サイズは**スプライトの高さの整数倍**に丸める。半端な倍率だと1ドットが3pxだったり4pxだったりと不揃いになる |

背景の手前には**床の平面**を別レイヤーとして重ねる。床の上端がキャラクターの立ち位置になる。

## キャラクター表示

自キャラ・敵キャラの双方に表示する（`CharacterFrame.vue`）。

| 要素 | 内容 |
|---|---|
| スプライト | `PixelSprite`。通常は `idle`、行動中は `attack` フレーム |
| 足元の影 | 楕円のグラデーション。無いと地面から浮いて見える |
| 予告チップ | 敵のみ。**頭上**に Next / 技名 / 被害の見込みを浮かせる |
| HPプレート | **足元**に名前・HPバー・現在値/最大値を置く |
| シールド | 残量がある場合のみ、HPバーの上に縞で重ねる |

敵は床の際に立ち、自キャラは全身が見える高さに置く。

> **決定（改修時）**: 当初は参考画面に倣い HP・予告をキャラクターの身体に重ねていたが、
> 文字がドット絵の上に乗って読みにくく「HPと予告が身体と被って見える」という指摘を受けた。
> 予告チップ（頭上）→ 本体 → HPプレート（足元）を**通常のフローで縦に積むだけ**の構成に変え、
> 絶対配置の座標合わせに頼らず構造的に重なりを防ぐようにした
> （自キャラを画面下端で見切れさせる旧配置も、HPプレートが画面外に出てしまうためやめた）。

### 見た目の出どころ

| 対象 | スプライトIDの指定場所 |
|---|---|
| 敵 | `src/data/enemies/*.json` の `sprite`（[07-data-schema.md](07-data-schema.md)） |
| プレイヤー | `src/data/config/battle.json` の `playerSprite` |

プレイヤーは**奥の敵の方を向いた後ろ姿**として描く（プレイヤーの視点＝画面の手前側に立たせるため）。

### 行動中の見た目

行動する側は `attack` フレームに差し替わり、CSS で相手側へ踏み込む
（敵は手前へ、プレイヤーは奥へ）。**これは行動順がどちらでも同じ**。

### 被弾の見た目

被弾した側は一瞬だけ単色のシルエットになる。色は原因で変える。

| 状況 | 色 |
|---|---|
| ダメージ | 赤 |
| シールドで受けた | 青 |
| 回復 | 緑 |

`PixelSprite` の `tint` に色を渡すと全セルがその色で塗られる。
フィルタではなく塗り替えなのは、ドット絵の輪郭を保ったまま確実に色が変わるため。

同時に、被弾点から**8方向へドットが飛ぶ**（`.hit-burst`）。色はフラッシュと同じ。
円やぼかしを使わず正方形のまま飛ばすのは、背景・キャラクターと同じ粒度に見せるため。

### 技ごとのレベル・クールタイム表示

自キャラの身体の下ではなく、COMMAND の `BATTLE` で開く技の一覧（`SkillCommandPanel`）に表示する。

| 表示 | 内容 |
|---|---|
| レベル | `Lv2` 等（一覧の右端） |
| スタック・詳しい効果文 | 常時表示のスキル一覧パネル、または `INFO` の詳細表示 |
| クールタイム | 残ターン数。技の一覧で数字バッジとして出す |

クールタイム中の技は**選択不可**とし、視覚的にも区別する（暗くする等）。

### 敵の撃破表示

撃破された敵は配列から削除されない（`alive: false`）。表示上は**撃破済みと分かる形で残す**（暗転・グレーアウト）。位置関係が変わらないことを視覚的に示すため。

## キャラクター詳細表示

**自キャラ・敵キャラともにクリックで開く。**

| 表示内容 | |
|---|---|
| 10ステータス | **実効値**および**基礎値** |
| 特性 | 所持している特性の一覧 |
| パッシブスキル | 同上 |
| アクティブスキル | 同上 |
| フレーバーテキスト | 上記それぞれのもの |

### 敵の行動パターンは非公開

**`actionPattern` の並びは表示しない。** 「どのスキルを持っているか」は分かるが「どの順で使ってくるか」は分からない。

次に使うスキルは敵の頭上の予告チップで1手先だけが読める、という情報量に留める。

### 既見フラグの更新

**敵の詳細表示を開いた時点**で、その敵の所持スキル・特性に既見フラグを立てる。

## 敵の予告

行動順の一覧を別枠で持たず、**敵の身体の上**に次の一手を出す。

| 表示 | 内容 |
|---|---|
| Next | 見出し |
| 技名 | 次に使うスキル（`previewEnemyNextSkill`） |
| 被害の見込み | `小ダメージ` 〜 `致命傷`（`domain/battle/damagePreview.ts`） |

被害の見込みは、実ダメージと同じ式で「命中・非クリティカル」として計算した値を
プレイヤーの最大HPと比べて段階に落としたもの。守るべきか攻めるべきかを、
数字を読まずに判断できるようにするための表示。

## 行動の選び方

```
COMMAND ─┬─ BATTLE ─┬─ 技（対象が1体しかいない）→ 即実行
         │          └─ 技（敵が複数）→ 対象選択 → 敵をクリック
         │          └─ もどる
         └─ INFO ── 大きく詳しい表示（CharacterDetail）を開く
```

COMMAND は画面右寄り・**プレイヤー側の高さ**に置く（右下の説明書パネルとは高さで避ける）。
`BATTLE` を押すと COMMAND の位置に技の一覧（`SkillCommandPanel`）へ切り替わる。
この切り替えは Vue の `<Transition>` ではなく、**新しく挿入されたパネル自身に掛かる
CSS の入場アニメーション**（`@keyframes menu-pop-in`）で表現する。

> **決定（改修時）**: `<Transition mode="out-in">` は退場側の完了を
> `getComputedStyle` の transition-duration 検出に頼っており、実CSSアニメーションが
> 走らないテスト環境（happy-dom）では退場が終わらず新パネルが差し変わらなかった。
> CSS `animation` は要素の挿入と同時に自動再生されるため、この非同期の完了待ちが要らない。

対象選択中は該当の敵が光る。専用のセレクタコンポーネントを置かず**敵そのものをクリック**
させるのは、選ぶ対象と押す場所を一致させるため（`CharacterFrame` の `targetable` で光らせる）。
`side: 'self'` かつ `range: 'single'` のスキル（自己回復等）は**対象が自明なため選択をスキップする**。

| 表示 | 内容 |
|---|---|
| TURN M | `roundCount + 1`（1ラウンド = 全員が1回動く） |
| 第N戦 | `battleIndex + 1` |
| 手番 | `あなたの手番` / `<敵名>の手番` |

## スキル名の提示（`SkillCastBanner`）

行動が解決される**前**に、誰が何を使うのかを敵と自キャラの間の高さに札で出す。
属性色（物理=橙赤 / 魔法=青 / 特殊=紫）で縁取る。

- **プレイヤーと敵で同じ形式**にする（行動順がどちらでも手応えを揃えるため）
- 敵のHPバー・予告チップを隠さない高さに置く
- 同じスキルを連続で使ってもアニメーションを撃ち直す（`presentation.seq` をキーにする）

> **決定（改修時）**: 「自分の手番であることを示す斜めの帯」（`TacticsBanner`）は
> 画面が賑やかになりすぎる・盤面の演出と喧嘩するとの指摘で**廃止した**。
> 手番の主張は `TurnBadge` の手番表示と、入力待ちで COMMAND が出ること自体に任せている。

## ドラフト画面（`SkillDraftPanel`）

3つの選択肢をカードとして横に並べる。各カードに表示するもの:

| 表示 | 内容 |
|---|---|
| 名前 | スキル・特性名 |
| 種別 | アクティブ / パッシブ / 特性 |
| カテゴリ | メイン（+サブがあれば併記） |
| 効果 | `SkillText` による色分け表示 |
| フレーバーテキスト | |
| 重複取得の場合 | `Lv2 → Lv3` のようにレベル変化を明示 |
| 解放枠の場合 | 「解放」バッジ |

アクティブスキルを選んで枠が全て埋まっている場合、**入れ替え先を選ぶ画面へ遷移する**。キャンセルでドラフト選択へ戻る。

## 色の扱い

**色は CSS 変数として定義し、ハードコードしない。** 既存の `GENRE_THEME_COLORS`（`src/data/config/genres.json`）と同じ流儀に従う。

必要な色:

| 用途 | 変数名（案） |
|---|---|
| 属性: 物理 / 魔法 / 特殊 | `--battle-element-physical` 等 |
| ステータス名 | `--battle-stat` |
| 数値 | `--battle-number` |
| バフ差分（正 / 負 / 補足） | `--battle-diff-plus` / `--battle-diff-minus` / `--battle-diff-muted` |
| カテゴリ11種 | `--battle-category-<id>` |
| アクセント（見出し・強調） | `--battle-accent` |
| パネル地色 | `--battle-panel` |
| 文字色 | `--battle-text` |

`--battle-accent` と `--battle-panel` は**背景JSONが上書きする**（`BattleScreen` が
インラインスタイルで注入）。草原では金、荒れ地では朱、遺跡では藤色というように、
戦っている場所に合わせてUIの色も変わる。他の変数は `.battle-screen` に既定値を持つ。

パネル類は `color-mix()` で半透明にし、背景の上に重ねても地形が透けて見えるようにする。

## エッジケース

| ケース | 扱い |
|---|---|
| 敵が3体を超える | 横に並べる。上限は `battle.json` で定義し、はみ出さない範囲に収める |
| スキル一覧が長い | パネル内でスクロールさせる。画面全体はスクロールさせない |
| 詳細ポップアップが画面外にはみ出す | 表示位置を反転させる |
| 折りたたみ状態でドラフト発生 | ドラフト画面はパネルより前面に出す |
| 敵が全員撃破済みの瞬間 | ドラフトへ遷移するまでの間、撃破演出を再生する |

### プレイフィードバックを受けた再構成（7回目の改修）

| 変更 | 理由 |

| `InfoPanelShell.vue` の `.info-shell-overlay` を `position: absolute` から `position: fixed` に変更 | ヘルプ（`HelpGuide.vue`）の呼び出し元 `.help-guide` が `position: absolute` かつ幅・高さを持たない34×34pxのアイコンボタンだったため、子オーバーレイの `inset: 0` の containing block がそのアイコンサイズに縮み、パネル全体がアイコンの近くに小さく崩れて見切れていた。`position: fixed` にすることで、どんな小さい呼び出し元からでもビューポート基準で正しく中央表示されるようになる（INFO側は元々 `.battle-screen`（全画面）が直接の親だったため症状が出ていなかった） |
| `useBattleState.ts` の表示用ヘルパー5関数（`effectiveOf` / `nextEnemySkillPreview` / `estimateDamageToPlayer` / `categoryPointsOf` / `categoryContributions`）で、`toRaw(c) as Combatant` を `c as unknown as Combatant` に変更 | **実装当初からの潜在バグ**。`toRaw()` は Vue のリアクティブ Proxy を完全に迂回するため、その先で読む `passives`/`traits`/`temporary` への依存が一切追跡されず、これらに依存する `computed`（ステータスパネル・INFOの実効値表示など）がパッシブ/特性を取得しても再計算されない不具合になっていた（`baseStats` だけは直接読んでいるため追跡されるが、これは戦闘中不変）。5関数はどれも引数を読むだけで書き換えないため、型だけ迂回する cast に置き換えてリアクティビティを保った |

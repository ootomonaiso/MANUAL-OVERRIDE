# RPG ジャンル 仕様書（メイン）

設計文書: [rpg-genre.md](rpg-genre.md)
指示元: [CLAUDE_OWNER.md](../../../CLAUDE_OWNER.md)

## 目的

`rpg` ジャンルを「マップ探索を持たず、戦闘のみを繰り返すローグライクRPG」として実装する。

現状の `rpg` は `exp` を拾ってもスコアが増えるだけで成長要素が存在せず、`enableFeatures` が `dungeon` と完全一致した複製ジャンルである。これを固有の戦闘システムを持つジャンルへ作り直す。

## スコープ

### 対象

| 領域 | 内容 |
|---|---|
| 戦闘システム | ターン制戦闘のロジック一式（行動順・ダメージ計算・命中判定・スキル効果） |
| 成長システム | ドラフト（3択）・スキルレベル・カテゴリポイント・特性 |
| データ定義 | スキル・特性・敵の JSON スキーマとローダ |
| UI | 戦闘専用のメニューUI一式 |
| 統合 | `genreLocked` 以降の画面切り替え、スコア確定、投擲フェーズへの接続 |

### 対象外

| 領域 | 理由 |
|---|---|
| マップ・探索 | 設計文書で明示的に見送り |
| 他ジャンル（特に `dungeon`）の挙動変更 | 現状 `rpg` と `enableFeatures` が同一だが、`dungeon` 側は現行仕様を維持する |
| スコア式の確定 | 設計文書で「実装後に持ち越し」 |
| ボスの出現タイミング | 同上 |
| カテゴリ特化の解放しきい値 | 同上 |

「実装後に持ち越し」の3項目は**暫定値を置き、JSON 等で後から差し替え可能な形**で実装する。

## ユーザー確認の結果（S4、2026-09-02）

仕様策定中に、設計文書に記述がなく推測で埋めた14件について確認を取り、**全件が確定した。**

| # | 論点 | 決定 | 該当 |
|---|---|---|---|
| Q1 | 回復・バフ・シールド付与に命中判定を行うか | **行わない**（敵を対象とする効果のみ判定） | 03 |
| Q2 | 敵のスキルがクールタイム中のときの挙動 | **飛ばして次の使用可能スキルへ**。全てCT中なら何もしない | 04 |
| Q3 | シールドは戦闘をまたいで持ち越すか | **持ち越す**（無期限のため） | 04 |
| Q4 | 戦闘間の引き継ぎ | **現在HPとシールドのみ引き継ぐ。** バフ・デバフ・クールタイムはリセット | 04 |
| Q5 | スキルレベルの倍率は何に掛かるか | **連続量のみ**（`repeat.times` や相性段階には掛からない） | 05 |
| Q6 | 初期スキルのクールタイム | **0** | 05 |
| Q7 | シールドの重ねがけ | **加算**（上書きしない） | 05 |
| Q8 | 効果文の数値表示 | **レベル適用後の実値**を表示する | 05 |
| Q9 | 保管中スキルはカテゴリポイントに寄与するか | **しない** | 06 |
| Q10 | 敵の既見フラグを立てるタイミング | **詳細表示を開いた時点** | 06 |
| Q11 | 敵のスキルレベル | **JSON で指定可能。既定値は 1** | 07 |
| Q12 | ステータス表示パネルの負の差分表示 | **符号付きで表示**し色で区別する | 08 |
| Q13 | 保管中スキルのスキル一覧での表示位置 | **所持側**（セット中のアクティブの後） | 08 |
| Q14 | `seenIds` をラン間で永続化するか | **しない**（ラン内のみ） | 10 |

> **Q4 の補足**: HPを回復させないのは「ランに終わりを作る」ため。シールドは無期限の性質どおり持ち越すため、加護カテゴリが数少ない緩衝手段として機能する。

## 本ジャンルの構造的特殊性

**他の21ジャンルは「同じ横スクロールCanvasエンジン（`SideScroller`）のルール変奏」だが、`rpg` はジャンル確定後に Canvas を使わず戦闘専用のメニューUIへ完全移行する唯一の例外である。**

このため以下の既存前提が `rpg` には当てはまらない。

| 既存の前提 | `rpg` での扱い |
|---|---|
| `GenrePlugin` が Canvas 描画を担う | 戦闘中は Canvas 描画を行わない |
| `FeatureSystem` がフレーム単位で `preUpdate`/`update`/`render` | ターン制のため毎フレーム処理を行わない |
| `snapshot.playScore` を `SideScroller` から取得 | 戦闘システム側が供給する |
| `scroller.getStats()` が `ActionStats` を返す | 同上（プレイスタイル検出への影響を要検討） |

詳細と対応方針は [01-architecture.md](01-architecture.md) を参照。

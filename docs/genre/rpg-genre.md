## 概要

マップ探索は作らず、**戦闘のみ**を繰り返すローグライクRPG。敵が出現 → 行動を選択 → 撃破 → 3択からスキル/特性を1つ獲得（ドラフト）→ 次の戦闘、のループを繰り返し、最終的にボスに挑む。スキルの重複取得によるレベルアップ、属性相性、カテゴリ特化による強化が駆け引きの核。

## アーキテクチャ上の最大の変更点

他の21ジャンルは全て「同じ横スクロールCanvasエンジン（`SideScroller`）のルール変奏」だが、本ジャンルは**ジャンル確定後、横スクロールCanvasを使わず戦闘専用のメニューUIへ完全移行する**唯一の例外になる。マップ・移動・ジャンプ・障害物回避は行わない。

これに伴い、既存の `GenrePlugin`（Canvas描画委譲）・`FeatureSystem`（`preUpdate`/`update`/`render` によるフレーム単位処理）という前提そのものが `rpg` には当てはまらない。実装時は以下のいずれかの方針を選ぶ必要がある。

- **A. 既存の phase マシン（`title → tutorial → ... → genreLocked → throwing`）はそのまま使い、`genreLocked` 後の描画だけ Canvas から専用の戦闘UI（Vueコンポーネント）に差し替える**
- **B. 戦闘専用の新しい phase を追加する**

いずれにせよ `useGameState.ts` の phase 管理・`App.vue` の画面切り替えに、他ジャンルにない特別対応が必要。

## ゲームループ

```
戦闘開始（ジャンル確定時に初期スキルと初期ステータスをランダム決定）
  │
  ▼
敵が1体以上出現（enemies/*.json から選出）／敵は次に使うスキルを公開
  │
  ▼
行動順キューを構築（AGI + 特性を考慮）
  │
  ▼
キュー順に各キャラが行動
  │  ├ プレイヤー: アクティブスキル1〜4 / 守る / 何もしない から選択 → フォーカス選択
  │  └ 敵: actionPattern 配列に従い順にスキルを使用（ループ）
  ▼
効果解決（効果部品を順に連鎖実行）→ エフェクト再生
  │
  ▼
ターン終了処理（全アクティブスキルのクールタイムを1減算）
  │
  ├─ 敵が全滅 → ドラフト（3択）→ 次の戦闘へ
  ├─ プレイヤーが倒れる → ラン終了
  └─ 継続 → 行動順キューの構築へ戻る
```

## ラン（1回の遊び）の終了条件

- **ボスに勝利** → 終了（クリア）
- **プレイヤーが倒れる** → 終了（敗北）
- **プレイヤーが自分で終了を選ぶ** → 終了（ギブアップ相当）

ボスは通常の敵よりかなり強い1体を用意する。**何戦目にボスが出現するかは未定**（実装時に決定する）。

いずれの終了経路でも、既存の投擲フェーズ（`throwing`）へ遷移して説明書を投げ、`ending` に至る流れは他ジャンルと共通とする。

## ステータス（10種）

| 区分 | 項目 | 内容 |
|---|---|---|
| 基本6種 | `HP` | 体力 |
| | `STR` | 物理攻撃力 |
| | `DEF` | 物理防御力 |
| | `INT` | 魔法攻撃力 |
| | `REF` | 魔法防御力 |
| | `AGI` | 速度（行動順、回避率、一部スキルの効果参照元） |
| 追加4種 | `命中率` | 攻撃が当たる確率 |
| | `回避率` | 攻撃を回避する確率 |
| | `クリティカル率` | クリティカル発生確率 |
| | `クリティカルダメージ倍率` | クリティカル時の倍率 |

プレイヤー・敵の双方が同じ10ステータスを持つ。

### 初期ステータス

**`HP` は他のステータスより1桁大きい**。ダメージがステータスの数十%オーダーで算出されるため、`HP` を同じ桁にすると1〜2発で戦闘が終わってしまう。`HP` だけスケールを分ける。

| ステータス | 初期値 |
|---|---|
| `HP` | **6000〜8000**（他より1桁大きい。要バランス調整） |
| `STR` / `DEF` / `INT` / `REF` / `AGI` | 600〜800 の範囲でランダム |
| `命中率` | 95% |
| `クリティカル率` | 5% |
| `クリティカルダメージ倍率` | 200% |
| `回避率` | 0% |

ただし**初期スキルに対応する攻撃ステータスのみ 700〜900** の範囲となる。

| 初期スキル | 優遇されるステータス |
|---|---|
| 叩く（物理） | `STR` が 700〜900 |
| ファイアボール（魔法） | `INT` が 700〜900 |

これにより、引いた初期スキルに応じたビルドの出発点が自然に決まる。

なお `DEF` / `REF` の初期値（600〜800）はカット率の等倍基準（1000）を下回るため、**開始時点のカット率は 0%**（下限）となる。基準を1000に置いているのは、初期値からわずかに伸ばすだけでカット率が動き始め、成長を実感できるようにするため。

## 実効値の計算方式（共通ルール）

10ステータスは、パッシブ・特性・一時効果による補正を受けた**実効値**として扱う。補正の合成方法を値ごとにバラバラに作らず、次の式を**全ステータス共通**で適用する。

```
実効値 = (基礎値 + 実数バフ) × 倍率バフ
```

- **基礎値**: そのステータス固有の出発点（下表参照）
- **実数バフ**: パッシブ・特性・一時効果（「避ける」等）による**加算・減算**
- **倍率バフ**: パッシブ・特性による倍率。**同種の倍率は加算スタック**（後述）で合算してから1回だけ乗算する

> 例: `STR +5%` のパッシブを2つ持つ場合、`1.05 × 1.05 = 1.1025` ではなく `1 + 0.05 + 0.05 = 1.10` を乗算する。

### 基礎値の決まり方

| 種別 | 対象 | 基礎値 |
|---|---|---|
| ランダム初期値 | `HP` `STR` `DEF` `INT` `REF` `AGI` | 「初期ステータス」参照（600〜800 等） |
| 固定初期値 | `命中率` `クリティカル率` `クリティカルダメージ倍率` | 固定値（95% / 5% / 200%） |
| 導出値 | `回避率` | `AGI` の実効値から導出（「回避率」参照） |

### カット率は10ステータスに含まれない

**カット率は実効値の対象ではない**。カット率は `DEF`/`REF` の実効値から**都度計算される中間結果**であり、それ自体に実数バフ・倍率バフが乗ることはない。カット率そのものを強化したい場合は、参照元の `DEF`/`REF` の実効値を上げるか、特性・シールドによる**別枠のカット率**（後述）を追加する形になる。

`回避率` は逆に、`AGI` から導出された値を**基礎値として**扱った上で、そこにさらに実数バフ・倍率バフが乗る（10ステータスの1つとして通常の実効値計算の対象になる）点が非対称なので注意。

> **実装時に確定させること**: 各ステータスの上限・下限クランプ（カット率0〜80%、回避率0〜80%等）を、実効値の計算式（実数バフ加算 → 倍率バフ乗算）の**後に**適用するのか、途中の導出値の時点でも適用するのかは未定。

## 計算値の名称（用語定義）

ダメージ・回復の算出は多段階にわたるため、各段階の値に名前を与える。以降の記述・実装ともこの名称に統一する。

| 名称 | 意味 |
|---|---|
| **基礎値** | ステータスの出発点（ランダム初期値 / 固定初期値 / 導出値） |
| **実数バフ** | ステータスへの加算・減算補正 |
| **倍率バフ** | ステータスへの倍率補正（加算スタック） |
| **ステータス実効値** | `(基礎値 + 実数バフ) × 倍率バフ`。実際の計算で参照される値 |
| **参照値** | スキルが参照するステータスの実効値（例: `STR` 参照なら `STR` のステータス実効値） |
| **スキル係数** | スキルが定める参照割合（例: 「`STR` の80%分」なら `0.8`） |
| **基本ダメージ** | `参照値 × スキル係数` |
| **クリティカル倍率** | クリティカル発生時は `クリティカルダメージ倍率`、非発生時は `1` |
| **効果倍率** | 攻撃側の特性・パッシブによる倍率（例: 「物理攻撃+50%」）。加算スタック |
| **送出ダメージ** | `基本ダメージ × クリティカル倍率 × 効果倍率`。**攻撃側の事情だけで確定する値** |
| **最終カット率** | 対象側のカット率の合計（上限80%）。ステータス由来・特性由来・シールド由来を合算 |
| **被ダメージ倍率** | `1 - 最終カット率` |
| **相性段階** | `(弱点の数) - (耐性の数)`。対象が持つ弱点・耐性を段階として合算した整数 |
| **属性相性倍率** | `2 ^ 相性段階` |
| **最終ダメージ** | `送出ダメージ × 被ダメージ倍率 × 属性相性倍率`。実際にHPから引かれる値 |
| **確定回復量** | 回復における「送出ダメージ」に相当する値（攻撃側で確定する回復量） |
| **被回復倍率** | 対象側の被回復量補正（加算スタック）。カット率・属性相性は**含まない** |
| **最終回復量** | `確定回復量 × 被回復倍率` |

### スタック規則

**同じ項目の補正は必ず加算で合成する**（例外なし）。

| 項目 | 合成方法 |
|---|---|
| 倍率バフ | 各補正値を合計してから1回だけ乗算 |
| 効果倍率 | 同上 |
| 最終カット率 | 各カット率を合計（上限80%でクランプ） |
| 被回復倍率 | 同上 |
| **相性段階** | 弱点を `+1`、耐性を `-1` として**段階を合計** |

例:

- 「物理攻撃+50%」を2つ持つ → `1 + 0.5 + 0.5 = 2.0`（`1.5 × 1.5 = 2.25` ではない）
- カット率20%の特性を2つ持つ → `20% + 20% = 40%`（`1 - 0.8 × 0.8 = 36%` ではない）
- `DEF` 由来のカット率30% + シールド20% + 特性10% → `60%`

### 相性段階（弱点・耐性の扱い）

弱点・耐性は**倍率をそのまま重ねるのではなく、段階として加算**してから倍率に変換する。

```
相性段階     = (弱点の数) - (耐性の数)
属性相性倍率 = 2 ^ 相性段階
```

| 状況 | 相性段階 | 属性相性倍率 |
|---|---|---|
| 弱点・耐性なし | `0` | `×1` |
| 弱点1つ | `+1` | `×2` |
| 耐性1つ | `-1` | `×0.5` |
| **弱点1つ + 耐性1つ** | `0` | `×1`（打ち消し合う） |
| 耐性2つ | `-2` | `×0.25` |
| 弱点3つ（将来、特性の重複を許可した場合） | `+3` | `×8` |

**この表現を採る理由**: 弱点`×2`・耐性`×0.5`を倍率のまま加算すると `1 + 1.0 - 0.5 = 1.5倍` となり、打ち消し合うべき場面で被ダメージが増えてしまう。かといって倍率のまま乗算すると「同じ項目は加算」という原則がここだけ破れる。**加算する対象を倍率ではなく段階にする**ことで、原則を維持したまま意図した挙動（弱点と耐性が打ち消し合う／弱点3つで8倍）が得られる。

副次的な利点として、「耐性を1段階強化する」「弱点を1段階打ち消す」といった特性を自然に表現できる（倍率を直接操作する設計では書きにくい）。

> **調整の余地**: 現状、相性段階に上限・下限は設けていない（弱点3つで8倍まで伸びる）。バランス調整の必要が生じた場合、`±2`（`×4`〜`×0.25`）程度でクランプする選択肢がある。

## 属性システム

属性は**物理 / 魔法 / 特殊**の3種。

| 属性 | 弱点・耐性 | カット率の参照元 |
|---|---|---|
| 物理 | あり | `DEF` |
| 魔法 | あり | `REF` |
| 特殊 | **存在しない（常に等倍）** | **`DEF` と `REF` の平均をさらに2で割った値** |

- 弱点属性で攻撃された場合: ダメージ **2倍** / 耐性属性の場合: **半減** / 何も持たない場合: **等倍**
- 弱点・耐性は**特性**として表現され、**相性段階**（弱点`+1` / 耐性`-1`）に合算されてから `2 ^ 相性段階` で**属性相性倍率**に変換される（「相性段階」参照）
- **弱点・耐性の特性は、原則としてドラフトの選択肢には出現しない**。弱点は取る動機がなく、耐性も含めて「敵が初期から持っているもの」または「スキル・特性によって付与されるもの」として扱う
- **特殊属性**は弱点も耐性も存在せず常に等倍。カット率の計算には **`DEF` と `REF` の平均をさらに2で割った値**（＝ `(DEF + REF) / 4`）を使う。これにより「物理か魔法のどちらかに極端に寄せたビルド」に対して有効打となり、逆に満遍なく育てた相手には通りにくい、という位置づけになる。平均をそのまま使うと、弱点2倍が乗らない分だけ特殊が一方的に不利になるため、さらに半減させて釣り合いを取る

**サポート系スキルも属性を持つ**。回復・シールド・バフといった直接ダメージを持たないスキルにも物理/魔法/特殊のいずれかを付与する。これは「魔法属性のスキルの効果を上昇させる」といった特性を、サポート系にも適用できるようにするため。

また、**属性と参照ステータスは独立**しており、「魔法属性だが `STR` を参照する」といった変わり種のスキルも許容する。

### カット率

カット率は防御ステータス（物理は `DEF`、魔法は `REF`、特殊は `(DEF + REF) / 4`）から次の式で求める。

```
カット率 = (防御ステータス - 1000) / 20000     ※下限 0%、上限 80%
```

| 防御ステータス値 | カット率 |
|---|---|
| `1000` 以下 | `0%`（**下限**。被ダメージが増えることはない） |
| `1000` | `0%`（等倍） |
| `11000` | `50%` |
| `17000` | `80%`（**上限**。これ以上は伸びない） |

- **下限0%**: 防御が極端に低くても被ダメージが等倍を超えることはない。マイナスのカット率（被ダメージ増）は発生しない
- **上限80%**: 完全無敵（カット率100%）には到達しない

等倍の基準を `1000` としているのは、初期値（600〜800）から**すぐに「上がっている感」を得られるようにする**ため。基準が高すぎると、序盤に防御を伸ばしても数値が動かず成長を実感できない。

### ダメージ計算の流れ

計算は**攻撃側で完結する部分**と**対象側の影響を受ける部分**の2段構えで行う。実装上もこの2つを別関数に分けること。

```
── 攻撃側（対象の事情に一切依存しない） ──────────────
  参照値       = 参照ステータスの実効値
  基本ダメージ = 参照値 × スキル係数
  送出ダメージ = 基本ダメージ × クリティカル倍率 × 効果倍率
                                                    ↑ ここまでが攻撃側で確定

── 対象側 ────────────────────────────────────────
  被ダメージ倍率 = 1 - 最終カット率          ※最終カット率は上限80%
  最終ダメージ   = 送出ダメージ × 被ダメージ倍率 × 属性相性倍率
                                              ↑ 弱点・耐性は最後に適用
```

**弱点・耐性はカット率を適用した後、最後に乗算する**。カット率で削られた後の値に対して倍率がかかるため、防御を固めていても弱点を突かれれば実質的に軽減効果が半減する。

#### 丸め処理

**丸めは「HPを増減させる直前」に1回だけ行い、方式は切り捨て（floor）とする。**

計算途中では小数をそのまま保持し、`最終ダメージ` / `最終回復量` が実際にHPへ適用される直前で切り捨てる。

```
2047.5 × 0.95 × 2 = 3890.25  →  切り捨て  →  3890 をHPから減算
```

- 対象はダメージ・回復の**両方**（HPが動くすべての箇所）
- ステータス実効値・カット率・各種倍率といった**中間値は丸めない**
- 途中で丸めないため、乗算の順序を入れ替えても結果は変わらない

同様に、**各種クランプ（カット率0〜80%、回避率0〜80%、実効命中率0〜100%）も最終値に対してのみ適用する**。途中の導出値の段階ではクランプしない（例: 回避率は `AGI` から導出した基礎値の時点ではクランプせず、実数バフ・倍率バフを適用した後の実効値でのみクランプする）。

#### 計算例

| 前提 | 値 |
|---|---|
| `STR` の基礎値 | 1000 |
| パッシブ | `STR +300`（実数バフ） / `STR +5%`（倍率バフ） |
| 特性 | 物理攻撃 +50% |
| スキル | 物理属性・`STR` を100%参照 |
| 対象 | 物理弱点持ち・`DEF` = 2000 |
| クリティカル | 発生せず（倍率 `1`） |

```
── 攻撃側 ──────────────────────────────────────
STRの実効値   = (1000 + 300) × 1.05         = 1365
基本ダメージ   = 1365 × 1.00                 = 1365
送出ダメージ   = 1365 × 1（クリ無し） × 1.5   = 2047.5   ← 攻撃側の確定値

── 対象側 ──────────────────────────────────────
最終カット率   = (2000 - 1000) / 20000       = 5%
被ダメージ倍率 = 1 - 0.05                     = 0.95
相性段階       = +1（物理弱点1つ）
属性相性倍率   = 2^1                          = 2
最終ダメージ   = 2047.5 × 0.95 × 2           = 3890.25

── HP反映直前 ──────────────────────────────────
切り捨て       = 3890                         ← 実際にHPから引かれる値
```

この流れは**敵からプレイヤーへの攻撃でも同一**である。

### 回復の計算の流れ

回復も**攻撃側で確定 → 対象側の補正**という同じ形をとるが、**対象側で適用する補正の中身が異なる**。

```
── 回復元側 ──────────────────────────────────────
  確定回復量 = 参照値 × スキル係数 × クリティカル倍率 × 効果倍率

── 対象側 ────────────────────────────────────────
  最終回復量 = 確定回復量 × 被回復倍率
```

**回復には最終カット率も属性相性倍率も適用しない。**

| 適用しない理由 | |
|---|---|
| カット率 | 適用すると `DEF` が高いほど回復量が減るという逆転が起きる |
| 属性相性 | 適用すると「物理弱点」を自分で取得した上で物理属性の回復スキルを使うと回復量が2倍になり、**弱点を意図的に取ることが最適解**になってしまう |

回復量を対象側で増減させたい場合は、**被回復倍率**（「被回復量+30%」のような専用の特性・パッシブ）で表現する。

なお回復スキルも属性を持つため、**回復元側の効果倍率**（「魔法属性の効果+50%」等）は通常どおり適用される。

### 回避率

回避率の**基礎値**は `AGI` の実効値から次の式で導出する。

```
回避率の基礎値 = (AGIの実効値 - 1000) / 50000
```

この基礎値に、「実効値の計算方式（共通ルール）」で定義した式をそのまま適用する。

```
回避率の実効値 = (回避率の基礎値 + 実数バフ) × 倍率バフ     ※最終的に 0%〜80% にクランプ
```

「避ける」による+50%は、この**実数バフ**として加算される（`AGI` 自体を上昇させるわけではない）。

| `AGI` の実効値 | 回避率の基礎値 |
|---|---|
| `1000` 以下 | `0%` |
| `26000` | `50%` |
| `41000` | `80%`（クランプ前の理論値。実効値の最終クランプで頭打ち） |
| `51000` | （式上は100%だが最終的に80%で頭打ち） |

回避はダメージを完全に無効化するため防御より強力である。そのため**カット率（`DEF` は11000で50%）に比べて意図的にスケールを2倍以上高く設定している**（`AGI` は26000で50%）。伸ばしにくいのは仕様であり、バグではない。

### 命中判定

命中率と回避率は**乗算**で合成する。

```
実効命中率 = 命中率の実効値 × (1 - 回避率の実効値)     ※0%〜100%にクランプ
```

ダメージ計算の `送出ダメージ × (1 - 最終カット率)` と**同じ構造**であり、「防御側のステータスが割合で減らす」という形が全体で統一される。

| 命中率 | 回避率 | 実効命中率 |
|---|---|---|
| 95% | 0% | 95% |
| 95% | 50% | 47.5% |
| 95% | 80% | 19% |
| 130% | 50% | 65% |
| 130% | 80% | 26% |

減算方式（`命中率 - 回避率`）を採らない理由は、命中率が回避率を1対1で打ち消してしまい、`AGI` 26000という高コストを要する回避投資が安価な命中パッシブで無効化されるため。乗算なら回避は常に一定割合を削るので、コストに見合った価値が残る。

#### 命中率の100%超え

**命中率は100%を超えてよい**。ただし超過分は**ダメージを増やさない**。回避率と打ち消し合いやすくなるだけの効果である（上表の130%の行を参照）。回避特化の相手に対する対抗手段として機能する。

#### 判定の単位

命中判定は**ヒットごとに個別に行う**（属性相性と同じ）。

この結果として、**多段ヒットスキルは回避持ちに対して安定**し（3連撃なら1〜2発は当たる）、**単発の大技はギャンブル**になる。スキル選択における意図的な駆け引きとして扱う。

#### 外れた場合の救済はない

クールタイムの長いスキルが外れた場合でも、**救済措置は設けない**（ダメージ半減の「かすり」や命中率の下限保証は導入しない）。クールタイム3の大技が外れれば3ターン分が無駄になる。

これは大技を選ぶことのリスクとして意図したものであり、多段ヒットスキルを選ぶ動機にもなる。被弾によるHP消耗への対処は、**回復スキルの獲得**または**自動回復の特性**という別のビルド選択で行う。

## アクティブスキル

- 専用の**アクティブスキル枠を4つ**持つ
- 使用には**ターンを1消費**する
- クールタイムは0以上の整数。使用時に設定され、**ターンごとに1ずつ減少**する（0で再使用可能）
- 属性（物理 / 魔法 / 特殊）を持つ。サポート系スキルも属性を持つ
- カテゴリを持つ（後述）

### 初期スキル

スキル枠1には初期スキルが1つセットされた状態で始まる。初期スキルは以下の2種で、**ジャンル確定時にランダムでどちらかがセットされる**。

| スキル | 属性 |
|---|---|
| 叩く | 物理 |
| ファイアボール | 魔法 |

ランダムにする理由は、プレイヤーが毎回同じ初期スキルから始めることで生じる**無意識のビルドの偏りを防ぐ**ため。スキル枠2〜4は初期は空。

### 常時選択できる行動

アクティブスキル4枠とは別に、以下の2つの行動が常に選択肢に並ぶ。

| 行動 | クールタイム | 効果 |
|---|---|---|
| **守る** | 3 | そのターンのみ、自身に **50% のダメージカット**を追加する |
| **何もしない** | 0 | 文字通り何もしない。動くと不利になる場面で使う |

「守る」は**3ターンに1回のみ**使用できる。

```
ターン1: 守るを使用
ターン2: 使用不可
ターン3: 使用不可
ターン4: 使用可能
```

常時使えると防御が一方的に有利になり、かつカット率上限80%に容易に到達してしまうため、意図的に間隔を空けている。

「何もしない」のクールタイムが0であるため、**全スキルがクールタイム中でも必ず行動できる**（行動不能による詰みが発生しない）。

一部の**特性により「守る」が「避ける」に変化**することがある。「避ける」はそのターンの**回避率の実効値に+50%の実数バフ**を与える。

「避ける」のクールタイムは「守る」と同じ **3** である（3ターンに1回のみ使用可能）。

### フォーカス（対象選択）

敵は1体以上出現するため、スキル使用時には**フォーカス**と呼ばれる対象選択を行う。

- 各スキルは**デフォルトフォーカス**を持つ（例: 回復系は自分、攻撃系は敵）
- プレイヤーはスキル使用時にフォーカスを変更できる

フォーカスの範囲には以下の種類がある。

| 範囲 | 内容 |
|---|---|
| 単体 | 選択した対象1体 |
| 全体 | 敵全体（または味方全体） |
| 隣接3体 | 選択した敵を中心に、その**左右1体ずつを含む3体** |

「隣接3体」が成立するため、**敵は左右方向に順序を持って並ぶ**必要がある。敵の並び順（フォーメーション位置）を状態として保持すること。

### 敵の次スキル公開

敵は**次に使用するスキルを公開する**。これによりプレイヤーは「守る」「避ける」を使うタイミングを判断できる。行動順キューと合わせて `TurnQueueBar.vue` に表示する。

## 行動順

行動順は **`AGI` とパッシブ・特性を考慮したキュー**として構築する。単純な `AGI` 降順ではなく、特性による割り込み・優先度変更を許容する設計にすること。敵が複数いるため、プレイヤーと全ての敵を1つのキューに並べる。行動速度はAGIを式に使用した実効値を用いますが特性による例外を許容します。

## スキル効果の記述方式（重要な設計方針）

スキルの効果は複雑な組み合わせを想定する。例:

> 敵1体に **STR** の **80%** 分の**物理**ダメージを **3回** 与える。最後の攻撃のみ**クリティカル率**上昇。

このような効果を**一連の流れとしてベタ書きで実装してはならない**。必要なのは、**スキルの部品ごとに関数を設計し、それを連鎖させる構造**である。

### 設計方針

- 効果は「オペレーション（部品）」の配列として JSON に記述する
- 各オペレーションは1つの純粋関数として `effectOps/` 配下に実装し、レジストリに登録する
- 新しい効果を追加したいときは、**新しいオペレーション関数を1つ足してレジストリに登録するだけ**で済むようにする（既存スキルへの影響ゼロ）
- オペレーションは互いに連鎖・入れ子が可能（`repeat` が内側に別のオペレーション配列を持つ、など）
- **属性と参照ステータスは別々に指定できる**こと（魔法属性で `STR` 参照、などを許容するため）

記述イメージ（構文は実装時に確定させる）:

```json
{
  "id": "skill_triple_strike",
  "label": "三連撃",
  "flavorText": "三度目に賭ける。それが作法だと教わった。",
  "kind": "active",
  "element": "physical",
  "mainCategory": "combo",
  "subCategories": ["might"],
  "cooldown": 2,
  "defaultFocus": "enemy",
  "focusRange": "single",
  "effects": ["fx_slash", "fx_hit_physical"],
  "effect": [
    {
      "op": "repeat",
      "times": 3,
      "body": [
        { "op": "damage", "element": "physical", "scale": { "stat": "str", "rate": 0.8 } }
      ],
      "onLastIteration": [
        { "op": "modifier", "stat": "critRate", "amount": 0.5, "scope": "thisHit" }
      ]
    }
  ]
}
```

「最後の攻撃のみ」のような**反復中の特定タイミングを指定する仕組み**が必要になる点に注意（上記案では `onLastIteration`）。インデックス条件で汎用化するか専用キーを設けるかは実装時に決める。

### クリティカルの適用範囲

クリティカルは**ダメージだけでなく回復・シールドにも適用される**。

例: `INT` の 80% 分を回復するスキルで、クリティカルダメージ倍率が 200% の場合、クリティカル時は **160% 分**の回復になる（80% × 200%）。

### 効果文の表示（色分け強調）

効果文の表示では、以下の要素を**色を分けて強調表示**する。

- ステータス項目名（`STR` / `INT` / `クリティカル率` など）
- 属性（物理 / 魔法 / 特殊）
- 数値（倍率・回数・実数）

`SkillText.vue` として専用コンポーネントを設け、効果データから表示文と強調範囲を生成する。効果文を手書きの文字列で持つのではなく、**効果データから自動生成する**方が、スキル追加時の記述漏れ・表示との食い違いを防げる（実装時に方式を判断する）。

## シールド

サポート系スキルで付与される**追加体力**。

- **期限は無期限**（時間経過やターン経過では消えない）
- ダメージを受けた際、**シールドの耐久値を優先的に消費**する
- シールドが存在する間、**あらゆるダメージに対して 20% のダメージカット**を持つ
- **特殊属性に対しては 40% のダメージカット**を持つ
- これらのカット率は、ステータス・特性によるカット率と合算され、**合計 80% の上限に従う**

特殊属性に対して通常より高いカット率を持つ点に注意（特殊属性は防御ステータスの平均を参照するため素通りしやすく、その対抗手段としてシールドが機能する）。

## パッシブスキル

- ターンを消費せず、**常に効果が適用される**
- アクティブスキル枠を**埋めない**（別枠管理）
- **基本的にステータス上昇に重きを置く**。重複取得によるレベル上昇で効果が伸びる
- カテゴリを持つ

## 特性

**パッシブスキルとは明確に区別される**、例外的な処理を担当する要素。

| | パッシブスキル | 特性 |
|---|---|---|
| 主な役割 | ステータス上昇 | 例外的な処理（例: 物理攻撃ダメージが200%になる代わりに〜） |
| 重複取得 | **可能**（レベルが上がる） | **不可**（1度取ると再出現しない） |
| カテゴリ | **持つ** | **持たない** |
| 枠の消費 | しない | しない |

- 弱点・耐性は**特性**として表現される
- 「守る」を「避ける」に変化させる、といった行動そのものの置き換えも特性が担当する
- 戦闘間のHP回復を付与する特性も検討対象（後述）
- プレイヤー・敵ともに**0個以上**の特性を持てる
- ドラフトではアクティブスキル・パッシブスキルと並んで特性も選択肢に並ぶ
- 重複しない性質上、一度取得した特性は以降の選択肢に現れない

## カテゴリとカテゴリ特化

アクティブスキル・パッシブスキルは**カテゴリ**を持つ（特性はカテゴリを持たない）。

同じカテゴリのスキルを多く取得すると**カテゴリポイント**が貯まり、**通常のドラフトには出現しない特別なアクティブスキル・パッシブスキル・特性**が解放される。これにより「同じカテゴリに絞って取ると強くなる」という特化型ビルドの方向性が生まれる。

### カテゴリの種類（11種、確定）

| カテゴリ | ID（JSON用） | 対応するステータス・性質 |
|---|---|---|
| **頑強** | `vitality` | `HP` |
| **守勢** | `guard` | `DEF` / `REF` |
| **剛撃** | `might` | `STR` |
| **明晰** | `wisdom` | `INT` |
| **疾風** | `swift` | `AGI` |
| **致命** | `fatal` | `命中率` / `クリティカル率` / `クリティカルダメージ倍率` |
| **治癒** | `heal` | 回復系の効果 |
| **加護** | `aegis` | シールド系の効果 |
| **呪詛** | `curse` | デバフ・弱点付与の効果 |
| **貫通** | `pierce` | 特殊属性・カット率踏み倒しの効果 |
| **連撃** | `combo` | 多段ヒットの効果 |

`命中率` は独立カテゴリを持たず、**致命に統合**する（命中率・クリティカル率・クリティカルダメージ倍率はいずれも「確実に急所を突く」という性質でまとめられるため）。

### メイン/サブカテゴリ

1つのスキルは**メインカテゴリを常に1つ**持ち、**サブカテゴリを0個以上**持てる。

- **メインカテゴリは「効果の形」で決める**。多段ヒットなら連撃、回復なら治癒、シールド付与なら加護、デバフ・弱点付与なら呪詛、特殊属性やカット率踏み倒しなら貫通、というように**効果の種類そのもの**を優先する
- 効果に際立った「形」がなく、**単純なステータス上昇のみ**を行うスキル（大半のパッシブ）は、上昇させるステータスに対応するカテゴリ（頑強/守勢/剛撃/明晰/疾風/致命）がそのままメインになる
- **サブカテゴリは、そのスキルが参照するステータス**に対応するカテゴリを付与する

> 例: `STR` を参照する3連撃スキル → メイン **連撃**、サブ **剛撃**
> 例: `INT` を参照するシールド付与スキル → メイン **加護**、サブ **明晰**
> 例: 単純に `DEF` を上昇させるパッシブ → メイン **守勢**、サブなし

サブカテゴリは**原則1個まで**を想定するが、拡張性のため2個を持つ「特別なスキル」を作れる余地は残す（後述のポイント計算がこれを前提にしている）。

### カテゴリポイント

所持しているスキル1種につき、その**メインカテゴリへ満額**、**サブカテゴリへは重み付けした値**が加算される。いずれも**スキルレベルに比例して増加する**。

**種別ごとの基礎ポイント（レベル比例）**:

| 種別 | Lv1 | Lv2 | Lv3 | Lv4 | 計算式 |
|---|---|---|---|---|---|
| アクティブスキル | 3 | 6 | 9 | 12 | `3 × レベル` |
| パッシブスキル | 1 | 2 | 3 | 4 | `1 × レベル` |

アクティブスキルはパッシブの3倍の重みを持つ。アクティブは4枠という上限があるため、1枠を同じカテゴリに割く判断の重さを反映している。

**サブカテゴリへの重み**: サブカテゴリの数 `N` によって、サブカテゴリ全体で分け合う重みの合計が変わる。

```
サブカテゴリ合計重み T(N) = 0.75 - 0.25 × (N - 2)²
各サブカテゴリの重み       = T(N) / N
```

| サブカテゴリ数 `N` | 合計重み `T(N)` | 各サブカテゴリの重み |
|---|---|---|
| 0 | ― | ― |
| 1 | 0.5 | 0.5 |
| 2 | 0.75 | 0.375 |
| 3 | 0.5 | 0.167 |

`N=2` を頂点に、`N=1` から `N=2` では合計重みが伸びる（複数の性質を併せ持つ特別なスキルへのボーナス）一方、`N=3` では再び下がる（サブカテゴリを乱造することへの抑制）。**原則1個まで、稀に2個の「特別なもの」**という運用方針とこの式が対応している。3を超えるケースは想定しておらず、式もその範囲では検証していない。

> 例: `STR` を参照する3連撃スキル（Lv2アクティブ、メイン連撃・サブ剛撃1個）を所持
> - 連撃（メイン）へ `3 × 2 = 6pt`
> - 剛撃（サブ、`N=1`）へ `6 × 0.5 = 3pt`

**重複取得によるレベルアップはカテゴリポイントも押し上げる**ため、「同じスキルを重ねる」ことと「同じカテゴリで揃える」ことが自然に噛み合う。

### 解放されるもの

解放される特別なスキル・特性は**レベル1固定**（重複取得によるレベルアップの対象外）だが、その分**非常に強力**である。

具体的に何が解放されるかは、実装後に個別のJSON定義として設計する。

特性自身はカテゴリを持たないが、「どのカテゴリで何ポイント貯めたら解放されるか」という**解放条件は解放される側（特性・スキル）のデータに持たせる**（カテゴリの所属と解放条件は別の概念）。

> **未確定**: 解放に必要なポイントのしきい値、および解放されたものがドラフトの3択にどう混ざるか（通常候補と同列に並ぶのか、別枠として提示されるのか）は未定。

## 戦闘間のHP回復

**戦闘間でのHP回復は行わない**。ダメージは次の戦闘に持ち越される。

ただし、**特性によって戦闘間の回復を付与する**ことは検討対象とする（「戦闘終了時にHPを一定量回復する」といった特性）。

## スキル獲得（撃破後のドラフト）

敵を倒すと**3つの選択肢**が提示され、1つを選んで獲得する。選択肢にはアクティブスキル・パッシブスキル・特性が並ぶ。

- **アクティブスキルを選んだ場合**: 空いているアクティブスキル枠にセットされる
- **アクティブスキル枠が全て埋まっている場合**: **入れ替えが可能**（後述）
- **パッシブスキル**: 枠を消費しないため常に候補になり得る
- **特性**: 未取得のもののみ候補になる（重複しない）
- **カテゴリ特化枠**: 同一カテゴリを一定数取得していると、特別なアクティブ・パッシブ・特性が候補に加わる
- **例外（打ち止め時）**: 獲得できるものが尽きた場合、代わりに**基本6ステータスのいずれかをランダムに微増させる**選択肢を表示する（3択の穴埋め用フォールバック）

### アクティブスキルの入れ替えとレベル保存

アクティブスキル枠が埋まっている状態でも、**既存のスキルと入れ替えることができる**。

**入れ替えはドラフトの選択を1回消費する**（ドラフトで新しいアクティブスキルを選び、それを既存の枠と入れ替える、という形になる）。入れ替えのためだけに別途の操作機会が与えられるわけではない。

入れ替えで枠から外れたスキルは、**そのときのレベルと重複スタック数を保持したまま**保存される。以降のドラフトでそのスキルが再び選択肢に出る場合、**保存された状態（レベルNのスタックM個）のまま**出現する。

> 例: Lv2・スタック1個の状態のスキルを入れ替えで外した場合、次にドラフトで出現するときも Lv2・スタック1個の状態で出てくる。積み上げた育成が入れ替えで失われることはない。

したがって、所持スキルの状態は「4枠にセット中のもの」だけでなく「枠から外して保管中のもの」も含めて保持する必要がある。

## スキルレベルアップ（重複取得）

同じスキルを重複して取得するとレベルが上がる。必要な重複取得数は次の通り（取得のたびにスタックが消費される）。

| レベル遷移 | 必要な重複取得数 | 累計取得回数（初回含む） |
|---|---|---|
| Lv1（初回取得） | ― | 1回目 |
| Lv1 → Lv2 | 1個 | 2回目 |
| Lv2 → Lv3 | 3個 | 5回目 |
| Lv3 → Lv4（MAX） | 5個 | 10回目 |

効果量はレベルごとに次の式で増加する（**確定**）。

```
倍率 = 2^レベル - 1
```

| レベル | 倍率 | 累計取得回数 | 1回あたりの平均価値（倍率÷累計回数） |
|---|---|---|---|
| Lv1 | ×1 | 1回 | 1.0 |
| Lv2 | ×3 | 2回 | 1.5 |
| Lv3 | ×7 | 5回 | 1.4 |
| Lv4（MAX） | ×15 | 10回 | 1.5 |

### 費用対効果について（解決済み）

当初 `2^(レベル-1)`（1, 2, 4, 8倍）で検討したところ、Lv4到達に必要な10回の取得を**別々のパッシブスキル10個に分散した場合の合計 ×10 を下回る**（8 < 10）という問題があった。これは特にアクティブスキル4枠のような上限がないパッシブスキルにおいて、「集中させるより分散させた方が強い」という逆転を生む欠陥だった。

`2^レベル - 1`（1, 3, 7, 15倍）に変更したことで、**どの到達段階でも1回あたりの平均価値が1.0を下回らず、特にLv2とLv4到達時には1.5に達する**。10回を1つのスキルに集中させた場合の合計（×15）は、10個に分散させた場合の合計（×10）を常に上回るため、集中投資が分散に対して不利にならない。

ただし、**しきい値に届かない中途半端なスタックはその時点では無価値**のままである（例: Lv3まであと1個というところでランが終了した場合、その2個の重複取得は結果的に活きない）。「集中させたのに完成しなかった」というリスクは意図的に残しており、これはバグではなく駆け引きの一部とする。

#### 未入手スキルの開示段階

未入手のものは**スキル名のみ**を表示し、**アイコンは灰色**にする。効果の詳細は伏せられる。

- ドラフトの選択肢として表示された
- 敵が所持していた（敵の詳細表示で確認できた）

これにより、プレイを重ねるごとに「どんなスキルが存在するか」が少しずつ分かっていく。初見の発見を保ちつつ、既知の情報はいつでも参照できる。

### キャラクター表示

**自キャラ・敵キャラの双方**に以下を表示する。

- **HPバー**
- **現在HP / 最大HP** の数値表示

自キャラの下部にはアクティブスキルのアイコンを並べ、**各アイコンの下にそのスキルのレベルとスタック数**を表示する。クールタイム中はその残ターン数も表示する。

### キャラクター詳細表示

**自キャラ・敵キャラともにクリックすると詳細表示に遷移する。** 詳細では以下を確認できる。

- 10ステータスの**実効値**および**基礎値**
- 所持している**特性**
- 所持している**パッシブスキル**
- 所持している**アクティブスキル**

敵についても同じ内容を開示するため、プレイヤーは敵の弱点・耐性や手持ちのスキルを踏まえて戦術を組み立てられる。

**ただし敵の行動パターン（`actionPattern` の並び）は公開しない。** 「どのスキルを持っているか」は分かるが「どの順で使ってくるか」は分からない。次に使うスキルの公開（`TurnQueueBar.vue`）で1手先だけが読める、という情報量に留める。

### フレーバーテキスト

## 状態管理

プレイヤーが現在所持している以下の状態を保持する必要がある。

- **アクティブスキル4枠**それぞれの: スキルID / レベル / 重複スタック数 / 現在のクールタイム
- **枠から外して保管中のアクティブスキル**: スキルID / レベル / 重複スタック数（入れ替えで外したもの。レベルを保持したままドラフトに再出現する）
- **所持パッシブスキル**: スキルID / レベル / 重複スタック数（枠上限なし）
- **所持特性**: 特性IDのリスト（レベルの概念なし）
- **カテゴリ別の取得数**（カテゴリ特化の判定に使用）
- **既見フラグ**: スキル・特性ごとの「見たことがあるか」（未入手スキルの段階的開示に使用。所持状態とは独立）
- **10ステータスの現在値**（パッシブ・特性による補正適用後）
- **現在のシールド耐久値**
- **戦闘数・ボス撃破フラグ**（スコア計算とボス出現判定に使用）

既存の `player`（`Player` クラス, [entities.ts](../../src/game/entities.ts)）を拡張するか、`useBattleState.ts` 側で独立した `BattleState` として持つかは実装時に決定する。

## 計算式一覧（参照用）

本文書で登場する計算式を、状態（確定 / 暫定 = 数値は決めたが検証未了 / 未定 = 形自体が未確定）と合わせて一箇所にまとめる。詳細は各セクション参照。

### 実効値

| 式 | 状態 |
|---|---|
| `実効値 = (基礎値 + 実数バフ) × 倍率バフ` | 確定（全ステータス共通ルール） |
| `倍率バフ`: 同種の倍率を**加算スタック**で合算（`1 + 0.05 + 0.05 = 1.10`） | 確定 |
| `回避率の基礎値 = (AGIの実効値 - 1000) / 50000` | 暫定 |
| クランプは倍率バフ乗算後（最終の実効値）にのみ適用 | 確定 |

### カット率・ダメージ

| 式 | 状態 |
|---|---|
| `カット率(物理) = (DEFの実効値 - 1000) / 20000` ※下限0%・上限80% | 確定 |
| `カット率(魔法) = (REFの実効値 - 1000) / 20000` ※下限0%・上限80% | 確定 |
| `カット率(特殊)の参照値 = (DEFの実効値 + REFの実効値) / 4` （↑と同じ式に代入） | 暫定 |
| 丸め: **HP増減の直前に切り捨て**（中間値は丸めない） | 確定 |
| クランプは最終値にのみ適用（途中の導出値では行わない） | 確定 |
| `相性段階 = (弱点の数) - (耐性の数)`（**加算**） | 確定 |

## 実装上の注意点

1. 本ジャンルは他ジャンルと異なり「横スクロールCanvasの変奏」ではなく「戦闘専用メニューUIへの完全移行」になる。`useGameState.ts` の phase 管理・`App.vue` の画面切り替えロジックに、他ジャンルにない特別分岐が必要。
2. **スキル効果はオペレーションの連鎖として実装すること**。個別スキルごとに専用ロジックをベタ書きすると、スキル追加のたびに実装が増え続け、本設計の意図（データ追加だけで拡張できる）が崩れる。
3. **同じ項目の補正は必ず加算で合成する**（倍率バフ・効果倍率・最終カット率・被回復倍率・相性段階）。弱点・耐性も例外ではなく、**倍率を乗算するのではなく相性段階を加算してから `2 ^ 相性段階` に変換する**。倍率のまま重ねる実装にすると、弱点と耐性が打ち消し合わなくなる（「相性段階」参照）。
4. **命中率は100%を超えうる**。クランプするのは `実効命中率`（`命中率 × (1 - 回避率)` の結果）であって、`命中率` 自体ではない。命中率の時点で100%に丸めると、回避特化の相手への対抗手段が失われる。
5. スキルレベルの効果倍率は `2^レベル - 1`（確定）。分散取得に対する費用対効果の課題は解決済み（「スキルレベルアップ」参照）。
6. クールタイムの減算タイミングは「ターンごとに1ずつ減る」という記述から**1ラウンド（全キャラの行動が一巡）につき1減算**と解釈している。異なる場合は実装時に修正する。
7. 「隣接3体」フォーカスが成立するため、**敵は左右方向の順序を持つ**必要がある。敵の並び順を状態として保持すること。
8. **`HP` だけスケールが1桁大きい**（6000〜8000 vs 他は600〜800）。ステータスを一律に扱う実装にすると、`HP` の初期値生成やパッシブによる上昇量で不整合が起きやすい。`HP` を特別扱いすることを型・データ設計に織り込むこと。
9. `rpg` と `dungeon` は現状 `enableFeatures` が完全一致した複製ジャンルだが、本設計により重複は解消される。`dungeon` 側の扱いは本文書のスコープ外。
10. スキル・特性・敵・エフェクトのJSON定義は、`src/data/cards/*.json` や `src/data/sfx/*.json` と同様のディレクトリ一括ロードの仕組みを流用する設計にすること。
11. **ステータス表示パネルは基礎値と実効値の両方を保持・参照できる必要がある**。実効値だけを計算して保持する実装にすると、基礎値表示・バフ差分表示が作れない。`BattleState` は基礎値を保持し、実効値は都度算出する（または両方をキャッシュする）設計にすること。
12. **操作環境はPCのみを想定する**（マウスオーバー前提のUIを含む）。タッチ環境への対応は考慮しない。
13. スキル・特性には「所持しているか」とは別に**「見たことがあるか」の既見フラグ**が必要（未入手スキルの段階的な開示に使う）。ドラフトでの表示・敵の所持を通じて立てる。

# Bullet Hell（弾幕STG）ジャンル設計文書

> **本文書のステータス: 設計のみ・未実装**
> `bullet_hell` は現状 TS プラグインを持たず、`enableFeatures` が `aerial_stg` と完全に一致した複製状態（`shoot, vertical_scroll, enemy_hp, spread_shot`）。CLAUDE.md 上の説明「弾幕回避ゲーム」と実態（自機が撃つだけの縦STG亜種）が食い違っている。本文書はあるべき姿を設計し直したもので、実装前提のコード変更は含まない。**実装が完了したら、この文書を「現状の実装を記録する」形式（`tetris-genre.md` 等と同じ体裁）に書き直すこと。**

## 概要

画面上部中央に居座るボスが全画面的な弾幕を撃ち続け、プレイヤーはその隙間を縫って生き延びることを目的とするジャンル。自機も応戦するが、ボスを倒すためではなく命中数がスコアに乗るだけの「おまけ」であり、コアはあくまで回避＋生存。`stg`（宇宙）・`aerial_stg`（空）とは世界観・目的の両方で明確に差別化する。

```
└── game/systems/
    ├── ShootFeature.ts                # 変更: オートエイム角度計算を追加（bullet_hell固有分岐）
    └── BulletHellBossFeature.ts       # 新規: 常駐ボス管理・弾幕パターンスポーン・hitsOnBoss集計
```

既存の `boss` フィーチャー（`SpecialFeature.ts`）は「HPを持ち撃破可能」なボスを前提にした実装（`arena` / `hack_slash` が使用）であり、本ジャンルの「倒せない常駐ボス」とは性質が異なるため流用しない。新規 FeatureId（仮称 `boss_stationary`）を追加し、別クラスとして実装する。既存ジャンルの `boss` 挙動に影響を与えないことが必須。

## ジャンル収束条件

| パラメータ | 閾値 |
|-----------|------|
| `vertical` | 4 |
| `enemy`    | 8 |

現行の `bullet_hell.json` の thresholds を維持する想定（再設計により変更が必要かは実装時に再検討）。カードプールでは `c-enemy-aerial`（`enemy+2, vertical+1`）・`c-vertical-stage`（`vertical+2, aerial+1`）などが該当軸に寄与する。

### 収束のしくみ

ベイズ収束方式（主方式）に準拠。他ジャンルと同様、専用の収束ロジックは持たない。

## ゲーム仕様

### 核となる体験

- **ボス**: 画面上部中央に固定。HPを持たず倒せない。常時、全画面的な弾幕を発射し続ける（今回は意図的に「倒せない」仕様。将来ボスを撃破可能にする拡張の余地は残す）
- **自機の攻撃（3方向オートエイム）**: 中央弾はボスの位置へ角度が追従（自動照準）。左右2発は中央弾からの固定オフセット角度（既存の `three_way`/`spread_shot` の分岐をそのまま踏襲）。ボスに近い・良い位置に陣取れば3発とも命中する
- 命中してもボスは怯まず消えない。命中数 `hitsOnBoss` を独立したカウントとして集計し、スコアに反映する
- **被弾**: HP制（数回の被弾を許容）。既定値は共通の `defaultPlayerMaxHp`（3）を踏襲する想定（要チューニング）
- ボスに近づくほど命中率は上がるが、弾幕密度も高いエリアになるため被弾リスクも上がる、というハイリスク・ハイリターンの位置取りが核

### 操作方法

| キー | 動作 |
|------|------|
| ← → | 左右移動 |
| ↑ ↓ | 上下移動（`scrollAxis: 'y'`） |
| Space | （縦STGのため未使用。ジャンプ相当の割り当てなし） |
| z | 射撃（3方向オートエイム） |

### スコア計算

```
survivedSec × 15 + hitsOnBoss × 25 + maxHitCombo × 40
```

- `survivedSec`: 生存時間。回避が主軸であることを反映し比重を最も高くする
- `hitsOnBoss`: ボスへの命中数。攻撃はスコアボーナスの位置づけ
- `maxHitCombo`: 被弾せずに連続命中させた最大数。被弾でリセット。位置取りの上手さを評価する項
- 上記の係数は初期値・要チューニング。実装後に実プレイで調整すること

## ビジュアル

東方Project的なファンタジー弾幕STGとして、`stg`（宇宙）・`aerial_stg`（空）とは明確に異なる世界観にする。

- **背景**: 黒背景。桜の花びら・お札のような装飾が薄く浮遊するパララックス層を追加
- **ボス**: 少女シルエット。画面上部中央付近に浮遊し、僅かな揺れ（idle sway）アニメーションを持たせる
- **弾（ボスの弾幕）**: 円形。青枠＋白塗り（仮色: 枠 `#4a90ff` / 塗り `#ffffff`。`visual.palette` で調整可能にする）
- **自機**: 東方風キャラクターを後ろ姿（背面）で描画する。他ジャンルの自機は進行方向を向く描画が基本だが、本ジャンルは常に背面固定である点に注意（既存の `spriteFacesUp` とは別の描画方針として `BulletHellPlugin.drawPlayer` 内で完結させる）
- **フィールド幅**: 既存の縦STG共有セーフゾーン（`hud_safezone.json` の `vstgLeftRatio`/`vstgRightRatio` = 0.225）をそのまま使用する。専用でさらに狭めることはしない（する場合はジャンル単位オーバーライドの新規実装が必要になるため、今回は見送り）

## 実装上の注意点

1. `spread_shot` は現状 `three_way` と完全に同一の実装（[ShootFeature.ts:101](../../src/game/systems/ShootFeature.ts#L101)、同じ3方向弾を撃つだけ）。オートエイムを追加する際、この共有分岐に `bullet_hell` 固有の角度計算を割り込ませるか、`spread_shot` 自体を拡張するかは設計判断が必要。`aerial_stg` など他ジャンルの `spread_shot` 挙動に影響を与えないこと。
2. 既存の `_spawnHazard`（[sideScroller.ts:1382](../../src/game/sideScroller.ts#L1382)）は「一定間隔で1体だけランダム位置に出現」という設計で、同時多方向弾（弾幕パターン）を出す仕組みは存在しない。既存のスポーンテーブル/weight方式と統合するか、ボス専用の別経路として実装するかは要検討。
3. 既存の `boss` フィーチャー（`SpecialFeature.ts`）は撃破可能なボスが前提（HP減少→撃破でスコア・演出）。本ジャンルの「倒せない常駐ボス」はこれと性質が異なるため、別FeatureIdとして実装し、既存の `arena` / `hack_slash` の boss 挙動を壊さないこと。
4. `hitsOnBoss` / `maxHitCombo` のようなジャンル固有統計を追加する場合、`scoreCalc.ts` の `ScoreVars` 型定義と `evalScoreFormula` の対応変数リストの両方を更新する必要がある（片方だけ更新すると式が無言で0扱いになる）。
5. 現行の被弾判定（`_updateVertical` 内、[sideScroller.ts:646-667](../../src/game/sideScroller.ts#L646-L667)）は HP機構を持たないジャンルでは実質1発ミス。`hp` フィーチャーを有効化してHP制にする場合、既存の `RpgFeature`（`hp` を handles に持つ）が想定通り縦STGでも機能するか実装時に確認すること。

## 今後の改善候補

- ボスを段階的に撃破可能にする拡張（フェーズ制・複数ボス等）。今回は意図的に見送り、常駐・不撃破の仕様とする
- 弾幕パターンのバリエーション（放射状・扇状・波状など）。具体的なパターン形状は本文書時点では未確定で、実装時に別途設計する
- `bullet_hell` 専用にフィールド幅を共有設定よりさらに狭める場合、`hud_safezone.json` のジャンル単位オーバーライド機構が新規に必要

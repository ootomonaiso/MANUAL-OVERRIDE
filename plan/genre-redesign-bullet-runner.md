## 概要（変更なし）

`runner` ジャンルを基礎とし、プレイヤー自身が `z` キーで射撃できるようにしたエンドレスランナー。敵は撃って倒す対象、障害物・ギミックは避ける対象として明確に区別する。

## 本セッションでの確定事項

| 論点 | 結論 |
|---|---|
| ↓キーの挙動 | **未使用**（何もしない）。Runner と統一 |
| 敵の移動パターン | **ステージと一緒に流れるだけ（自力移動なし）**。Runner のトゲ（敵）と同じ方針 |
| 敵の回避可否 | **ジャンプでの回避も可能**。射撃は必須ではなく選択肢の一つ（倒さずジャンプで飛び越えてもよい） |
| 弾・射撃パラメータ | 既存 `shoot.json` をそのまま流用。Bullet Runner 専用のチューニング値は新設しない |
| 生成方式 | **Runner の区間パターン（JSON）を基盤とし、敵は別レイヤーで重ねる**。穴・空中足場・バネ・トゲの配置は Runner と共通のパターンプールを使い、敵の配置だけを別ロジックで追加する |
| 敵の配置量の決め方 | 未指定（ユーザーからは「特にこだわりなし」との回答）。**提案**: 区間パターンJSONに「敵スポット」候補を複数マークし、プレイ時に確率抽選で敵を配置する方式とする。実装前に最終確認を取ること |
| スコア式 | 未指定（同上）。**提案**: `distance * 係数 + kills * 係数`（距離に加え、撃破数をボーナスとして加点）。実装前に最終確認を取ること |

## ゲーム仕様（更新）

### 核となる体験

- **基本システム**: [Runner の再設計](genre-redesign-runner.md) を継承する（自動右移動、二段ジャンプ、コヨーテタイム、ジャンプ入力バッファ、固定長の区間パターン、reach-sim 検証）
- **区間パターン**: Runner と共通のパターンプール（穴・空中足場・バネ・トゲの配置）を基盤として使用する
- **敵レイヤー**: 区間パターンとは別に、敵の出現を重ねて配置する。敵はステージと一緒に流れるだけで自力移動はしない
- **敵の撃破**: `z` キーで既存の `shoot.json` に基づく弾を射出する。敵はHPを持ち、被弾でHPが減少、0で撃破・消滅する
- **敵のHP表示**: 既存の HP バー描画をそのまま使用する
- **敵の回避**: 敵を撃破せずジャンプで飛び越える回避も可能（射撃は選択肢）
- **障害物・ギミック（穴・空中足場・バネ）との区別**: 敵とは明確に別カテゴリとして扱い、これらは射撃で破壊されない（Runner と同じ）

### 操作方法（変更なし）

| キー | 動作 |
|------|------|
| ↑ / Space | ジャンプ（二段ジャンプ対応） |
| z | 射撃 |
| ← → ↓ | 未使用 |

## ビジュアル（変更なし）

元ドラフトの記述（ネオン都市の夜、疾走感、敵HPバー、弾・穴・空中足場・バネの視覚区別）を維持。Runner 側で決定した「穴・空中足場・バネの視認性改善」は Bullet Runner にも及ぶ（共通パターンプールを使うため）。

## 実装上の注意点（更新）

- Runner の区間パターンJSONをそのまま流用し、Bullet Runner 専用の穴・空中足場・バネパターンは新設しない
- 敵の配置は区間パターンJSONとは別レイヤー（例: 区間ごとの「敵スポット」候補リスト）として管理し、確率抽選で配置する案を提案している。採用前に確認を取ること
- 弾とハザードの衝突判定では、敵にはダメージを与えるが、Runner 由来の穴・空中足場・バネなどのギミックには通常の破壊処理を適用しない（`isGimmick` フラグで区別する既存方針を維持）
- 敵の密度は Runner 単体より明確に高くし、射撃がゲームプレイの主要要素になる程度を確保する
- 大量の敵が同時に存在する場合の生成・更新・破棄負荷に注意する

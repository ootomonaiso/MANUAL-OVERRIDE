## 概要（更新）

要塞の最下層から、手作りされた「部屋（パターン）」を1つずつクリアしながら上へ登り続ける縦スクロール型プラットフォーマー。
部屋の下端付近の一方通行足場から出発し、部屋上端の一方通行足場（出口）に到達すると次の部屋へスクロールする。
画面下からは溶岩が迫っており、部屋をクリアするたびに溶岩の上昇速度が（上限付きで）増していく。

## 本セッションでの確定事項

| 論点 | 結論 |
|---|---|
| 生成方式 | **手作りパターン（部屋）方式に全面転換**。重み付きランダム生成（`spawnTable`）は廃止 |
| 画面レイアウト | 縦長、左右をパネルで埋める構図（縦STG参照、[Aquatic の決定](genre-redesign-aquatic.md) と共通） |
| 部屋の構造 | 画面底から少し浮いた位置に**一方通行足場**（下から上へジャンプで通過でき、上から着地もできる）を起点として設置。ゲーム開始時は必ず一番下から一番上（部屋上端の一方通行足場＝出口）まで到達可能なパターンで開始する |
| 部屋クリア | プレイヤーが部屋上端の一方通行足場（出口）に到達すると、画面がスクロールして次パターンの初期構図に切り替わる |
| パターンの定義形式 | JSON でパターン集を定義する（他ジャンルの JSON 駆動方針に準拠） |
| パターン選択 | プールからランダム（直前と同一パターンは除外） |
| 溶岩の挙動 | 部屋が切り替わるたびに**初期位置はリセット**（同じ相対位置から再スタート）。ただし**上昇速度は部屋クリア数に応じて上昇**する。上限を設け、攻略不可能な速度には到達しない |
| スコア（高度）集計 | クリアした部屋数 × 部屋高さの累積 |
| 透過足場（↓キーで下に抜ける） | **不要**。↓キーは使わない方針に変更。「一方通行足場」は物理挙動（上昇中は通過・下降中に着地）で自動判定し、キー入力を必要としない |
| 到達可能性検証（reach-sim） | **導入する**。`hack_slash` / `tetris` で使われた到達シミュレーション手法と同様の仕組みを、パターンJSONの検証に適用する |

## ゲーム仕様（更新）

### 核となる体験

- **目的**: 手作りされた部屋（パターン）を1つずつクリアし、可能な限り高い高度まで上昇する
- **部屋の構成**: 1パターン = 「部屋底の一方通行足場（起点）」から「部屋上端の一方通行足場（出口）」までの垂直な1区画。バネ・移動足場・コンベアなどのギミックを組み合わせて配置する
- **一方通行足場**: 下から上へジャンプで通過できる。落下中（下降時）は上から着地する通常の足場として機能する。↓キーによる能動的な「抜け」操作はない
- **部屋クリア**: 出口の一方通行足場に到達すると、画面がスクロールして次パターンの初期構図（部屋底の起点）に切り替わる。次パターンはプールからランダムに選ばれる（直前と同一パターンは除外）
- **溶岩**: 部屋が切り替わるたびに初期位置はリセットされ、同じ相対位置（部屋の下端付近、まだプレイヤーに追いつかない位置）から上昇を再開する。上昇速度は部屋クリア数に応じて徐々に上がるが、上限を超えない
- **高度（スコア）**: クリアした部屋数 × 部屋高さの累積で計算する
- **二段ジャンプ・コヨーテタイム・ジャンプ入力バッファ**: 既存の共通ジャンプ物理をそのまま使用（新規実装不要、`physics.json` / `gameBalance.ts` に既存）
- **バネ**: 踏むと通常より大きく上方向へ跳ね上げる
- **移動足場**: 水平方向に一定範囲を往復する足場（既存 `driftEnabled` を流用）
- **コンベア**: 乗っている間、プレイヤーを一定方向へ移動させる（既存 `conveyorVx` を流用）

### 操作方法（更新）

| キー | 動作 |
|------|------|
| ← → | 左右移動 |
| ↑ / Space | ジャンプ（二段ジャンプ対応） |
| ↓ | **使用しない** |

## ビジュアル（更新）

- 画面は縦長。左右をパネルで埋める構図（Aquatic と共通の考え方）
- 要塞の最下層から無限に登る。石造りの足場・松明・要塞の壁（既存 `PlatformerPlugin` の描画を踏襲）
- 一方通行足場は、通常の足場と視覚的に区別できるデザインにする（縁の強調など）
- その他の要素（溶岩・バネ・移動足場・コンベア・高度表示）は元ドラフトの記述を維持

## 実装上の注意点（更新）

- パターンは JSON で定義し（例: `src/data/patterns/platformer.json`）、部屋ごとに足場・バネ・移動足場・コンベア・一方通行足場（起点/出口）の配置を持たせる
- 各パターンには reach-sim による到達可能性検証を通す。バネ・移動足場・コンベアを組み合わせても、通常ジャンプ・二段ジャンプで出口まで必ず到達できることを機械的に保証する
- 部屋切り替え時、溶岩の初期位置は毎回リセットする。上昇速度のみを部屋クリア数に応じて増加させ、上限（`gimmicks.json` の `climbMaxScrollSpeed` 相当）を設ける
- 一方通行足場の当たり判定は、プレイヤーの垂直速度（上昇中か下降中か）で通過/着地を切り替える一般的な semi-solid platform ロジックで実装する
- 初期パターン数は Runner と同程度（目安20種以上）を推奨するが、この点は未確認のため実装前に確認を取ること

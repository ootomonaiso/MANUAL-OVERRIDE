## 概要（変更なし）

`base` ジャンルを基礎とし、移動を自動化してジャンプアクションと障害物対応に集中させたエンドレスランナー。操作は基本的にジャンプのみ。

## 本セッションでの確定事項

| 論点 | 結論 |
|---|---|
| 現状の問題点 | 敵・穴・空中足場・バネの組み合わせで到達不可能な配置が発生する／疾走感・スピード感が乏しい／「敵」が障害物と見分けがつかない |
| 生成方式 | **手作りパターン（区間）方式に変更**。Platformer と統一 |
| パターンの長さ | 全パターン共通の**固定長** |
| 難易度スケーリング | パターン選択は**均一確率**。**スクロール速度の時間経過による上昇のみ**で難易度を調整する（上限あり、Platformer の溶岩と同じ考え方） |
| 「敵」の実体・挙動 | 実体はトゲ（棘）に類する固定ハザード。**自力移動はしない**。ステージと一緒に流れるだけ（Bullet Runner の障害物方針と統一） |
| 視覚設計の見直し対象 | 穴（落下死）・空中足場・バネ・トゲ（敵）の**全て**。視認性を大きく改善する（明確な色分け・シルエット差別化が必要） |
| 初期パターン数 | 目安20種以上を最初から用意する |

## ゲーム仕様（更新）

### 核となる体験

- **目的**: 右方向へ自動的に走り続け、可能な限り長い距離を進む
- **自動移動**: プレイヤーは常に右方向へ移動する。左右方向の自由な移動操作はできない
- **区間パターン**: 全パターン共通の固定長を持つ区間を、JSON で手作りする。穴・空中足場・バネ・トゲ（敵）の配置は区間ごとに固定
- **区間の選択**: プールから均一確率でランダムに選び、区間を連結してエンドレスに走行させる
- **ジャンプ**: ジャンプによってトゲ（敵）・地形上の障害物を回避する
- **二段ジャンプ・コヨーテタイム・ジャンプ入力バッファ**: 既存の共通ジャンプ物理を継続使用
- **トゲ（敵）**: 右方向から出現するが自力では移動せず、ステージと一緒に流れる固定ハザード。接触で即死
- **穴**: 地面が途切れた場所。ジャンプで飛び越える
- **空中足場**: 地面から離れた位置にある足場。二段ジャンプなどで着地する
- **バネ**: 踏むとプレイヤーを大きく上方向へ跳ね上げる
- **距離**: 右方向へ進んだ距離をスコアとして評価する
- **難易度上昇**: 時間経過に応じてスクロール速度が徐々に上昇する。上限を設け、操作で対応不可能な速度には到達させない

## ビジュアル（更新）

- 昼の都市。空は明るい青、奥にビル街のシルエット、地面はアスファルト風（元ドラフトの記述を維持）
- **穴・空中足場・バネ・トゲ（敵）は視認性を最優先に再設計する**。地面・背景から明確に浮き上がる色分け・シルエットにし、種別ごとの見分けが一目でつくようにする
- トゲ（敵）は「障害物」ではなく脅威として認識できる形状・配色にする（現状の diamond/spike 形状の配色見直しを含む）

## 実装上の注意点（更新）

- 区間パターンは JSON で定義し（例: `src/data/patterns/runner.json`）、穴・空中足場・バネ・トゲの配置を固定長の区間として持たせる
- 各パターンには reach-sim（Platformer と同様の到達可能性検証）を適用することを推奨する。二段ジャンプを含めても回避不能な状況が発生しないことを機械的に保証する
- パターンはプールから均一確率で選び、直前と同一パターンを除外する運用を推奨する（Platformer の部屋選択と同じロジックを流用できる）
- スクロール速度の上昇は時間経過ベースとし、上限値を `game_balance.json` 等の既存難易度パラメータに準じて定義する
- コヨーテタイム・ジャンプ入力バッファは既存の共通実装をそのまま使う（Runner 専用の再実装は不要）
